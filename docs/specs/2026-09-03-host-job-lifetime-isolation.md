## 目标与非目标

让从 Codex 等受 Windows Job 管理的宿主中启动的普通 ZGSTokenBar 实例脱离宿主的终止生命周期，使 Codex 更新或退出不会连带结束 TokenBar。

本次不恢复 watchdog，不新增服务、计划任务、安装器或崩溃自动恢复，不改变单实例、登录启动、更新检查、Provider 活跃检测、插件子进程监管和用户配置语义。

## 现状与目标行为

2026-09-03 11:23 的 AppX 部署事件显示 Codex 使用 `ForceTargetApplicationShutdownOption` 完成更新。现场进程探针确认 Codex 任务启动的命令位于同时设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 和 `JOB_OBJECT_LIMIT_BREAKAWAY_OK` 的 Windows Job 中；由该任务直接启动的 TokenBar 会继承 Job，因此在 Codex 更新关闭该 Job 时被系统一并终止。同期没有新的 ZGSTokenBar 应用崩溃事件，当前登录启动项仍指向有效的便携版路径。

普通数据根启动在读取配置、协调登录启动项或竞争单实例互斥量之前检查当前进程的 Job 限制。如果所在 Job 会随句柄关闭而终止成员，程序选取同一登录会话的 Windows Explorer，使用公开的 `PROC_THREAD_ATTRIBUTE_PARENT_PROCESS` 创建隐藏的系统命令解释器，再由该解释器普通启动替代实例；成功后当前实例立即正常返回。Windows 会让解释器及替代实例继承 Explorer 的 Job 归属而非 Codex 的嵌套 Job，因此替代实例继续现有启动流程时不再受宿主更新影响。

## 决策、约束与范围

- 仅对默认数据根的桌面实例启用生命周期隔离；显式 `--data-directory` 或 `ZGSTOKENBAR_DATA_DIRECTORY` 启动仍由测试或调用方拥有生命周期，且不触碰全局启动状态。
- 发现 `KILL_ON_JOB_CLOSE` 时才重新启动；普通进程、无终止语义的 Job、缺少同会话 Explorer 和 Win32 探针失败均原地继续，不让隔离功能阻止应用启动。
- 使用一次性进程环境标记防止替代实例在异常桌面环境中重新启动循环；标记只控制本次启动链，不写磁盘或用户配置。
- 生产入口只向解释器转发默认数据根下实际支持的 `--settings` / `settings` 参数，忽略本来就没有行为的未知参数；显式数据根不会走解释器。替代实例命令按 Windows 引号规则重建，并显式传递当前 Unicode 环境块和工作目录；不依赖框架构建中可能指向 DLL 的 `Environment.CommandLine`，不继承可继承句柄。环境内容只传给同一应用，不写入日志或磁盘；所有新建的进程与线程句柄均由启动实例关闭。
- `Program.cs` 只增加主启动流程调用；Win32 Job 检测与脱离启动封装在新的 App 内部组件中。回归覆盖加入 .NET 纯决策测试和生命周期静态契约。

## 失败、兼容与恢复

如果 Job 查询、Explorer 访问或替代实例创建失败，程序记录不含参数、路径或配置内容的 Trace 警告并继续当前实例；最坏行为退化为本次修复前的宿主绑定生命周期。登录启动的普通实例通常不在终止型 Job 中，不产生额外进程。显式隔离数据根保持原行为。

源码回滚可删除生命周期隔离组件及入口调用并重新构建便携版；不会迁移或改写用户数据。已部署构建为未签名的本机自用包，不作为公开发布资产。

1. 默认数据根实例处于设置 `KILL_ON_JOB_CLOSE` 的 Job 且同会话 Explorer 可用时，在配置加载、启动项协调和单实例判定前成功创建继承 Explorer Job 归属的等价实例，并结束原实例。
2. 不在 Job、Job 不会随关闭终止、已尝试替代启动或使用显式数据根时不重新启动。
3. Job 探针或创建失败不会阻止现有应用启动，也不会泄露命令行、路径或配置内容。
4. 原始参数、工作目录和单实例行为保持兼容；不恢复 watchdog，不新增持久系统组件，不改变插件子进程的 Job 监管。
